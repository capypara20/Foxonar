トリガーとジョブのしくみ

設定の部品（監視フォルダ・トリガー・ジョブ・ステップ）が何を持ち、どうつながって動くか。設定ファイルでの書き方（キー名など）は、まだ決めていません（宿題一覧 9 章）。

1. 部品のつながり 2. トリガーに合うかの見方 3. 合っても発火しないとき 4. ジョブとステップ 5. 発火からランへ 6. ランの終わり方と記録

1. 部品のつながり

監視フォルダ
  • ID
  • パス
  • 見る深さ（書かなければ制限なし）
  • 監視フォルダの条件（隠しファイル、名前のパターンなど）
  • デバウンス時間
  • 止まっている間の扱い（必ず書く）
  • 覚えている中身が無いときの扱い（必ず書く）
1 つを ID で指す
トリガー
  • ID・名前
  • 監視フォルダ（1 つだけ）
  • 変化の種類（複数書ける）
  • 反応する対象・反応する深さ
  • フィルタ
  • ジョブ（1 つ以上）と、ジョブどうしの依存
1 つ以上を ID で指す
ジョブ
  • ID・名前
  • ステップ（順番に 1 つ以上）
  • ジョブごとの同時実行数の上限
  • ジョブごとの時間の上限
  • 中断したランを、自動でやり直すか
中に順番に
ステップ
  • コピー・移動・削除（組み込みのステップ）
  • プロセス実行
  • ステップごとの時間の上限
  • 1 つのトリガーが見張る監視フォルダは、1 つだけ。1 つの監視フォルダを指すトリガーは、0 個以上でよい（トリガーの無い監視フォルダは、検知ログだけを残す）。
  • 1 つのジョブを、複数のトリガーから使い回せる。同じジョブを別の監視フォルダでも使うときは、トリガーを分けて書き、同じジョブを指す。
  • ジョブどうしの依存は、ジョブではなくトリガーに書く。ジョブを使い回すと、一緒に走るジョブがトリガーごとに変わるため。

2. トリガーに合うかの見方

変化 1 つについて、トリガーごとに次の 5 つを見て、すべて合えば発火する。当てるのは変更後のパス（名前変更・移動なら、変わったあとのパス）。

見るところトリガーに書くこと例：トリガー photosC:\in\photos\cat.jpg の作成
監視フォルダ1 つinbox（C:\in）inbox で検知した ✓
変化の種類作成・変更・削除・名前変更・移動から 1 つ以上作成・名前変更作成 ✓
反応する対象ファイル・フォルダ・両方ファイルファイル ✓
反応する深さ数（すぐ下が 1 段目。書かなければ見る深さまで全部）書かない2 段目 ✓
フィルタ名前のパターン（glob か正規表現）。名前だけに当てる*.jpgcat.jpg ✓
  • glob（*.jpg、{*.jpg,*.png}）は名前全体に当てる。正規表現（^IMG_\d{4}）は名前の一部に合えばよく、全体に合わせたいときは ^ と $ を書く。
  • 大文字と小文字は OS に合わせる。Windows では区別せず（*.jpg は CAT.JPG にも合う）、Linux では区別する。
  • トリガーは検知には効かない。どのトリガーにも合わない変化も、検知ログには残る。
  • 名前変更・移動は、変更後のパスに当てる。たとえば反応する深さ 1 のトリガーは、inbox\a.pdf を inbox\done\a.pdf（2 段目）へ移した移動には反応しない。
  • 同じパスに複数のトリガーが合ったら、トリガーの定義順に、発火を 1 つずつ動かす。

3. 合っても発火しないとき

トリガーに合っても、次のときは発火しない（無視）。走るはずだったジョブごとに、ランログに「無視」の行を書くので、「なぜ走らなかったか」はランログで分かる。

場面発火しないトリガーランログの理由の例
ランが起こした作成・変更・名前変更・移動もとのトリガーだけ（ほかは発火してよい）自分が起こした変化（ラン 42）
ランが起こした削除（監視フォルダの外への移動も）どのトリガーもランが起こした削除（ラン 91）
来てすぐ消えた（デバウンスで作成と削除の組）どのトリガーも作成のあと削除された（検知 301〜302）
待ち表でまとめ直したら合わなくなった合わなくなったトリガーまとめ直したら、トリガーに合わなくなった（検知 302〜303）
待ち表で待つ間に、設定を読み直した消えた・変わったトリガー設定を読み直したら、トリガーが無くなった
待ち表で待つ間に、監視フォルダを見失ったその監視フォルダのトリガー監視フォルダを見失った
  • ランが起こしたと見分けられるのは、組み込みのステップ（コピー・移動・削除）が書いたパスだけ。プロセス実行のプログラム（robocopy /MOV など）が書いたものは、OS イベントに「誰が書いたか」が入っていないので見分けられない。
  • 例「ジョブが外へ移した」で、1 段ずつ追える。

4. ジョブとステップ

ジョブに書くこと意味
ステップ順番に 1 つ以上。常に逐次に走り、1 つ失敗したら残りは走らない（コピーに失敗したのに元を消す、を防ぐ）。
ジョブごとの同時実行数の上限同時に 2 つ動くと壊れるジョブ（同じ CSV に追記する、同時に 1 つしか起動できないプログラム）のため。全体の上限とは別。
時間の上限ジョブごと（ランが始まってから数える）と、ステップごと。超えたら止めて失敗。書かなければ上限なし。
中断したら自動でやり直すか次に起動したときに、新しいラン ID で最初のステップからやり直す。何度やっても同じ結果になるジョブ（変換など）向け。
ステップすること選べること失敗になるとき
コピー行き先へ写す行き先に同じ名前があったら上書きするか。行き先のフォルダが無ければ作るかOS がエラーを返した（権限が無い、容量が足りない、上書きしない設定で同じ名前がある、など）
移動行き先へ移す（同じフォルダの中での名前の変更も、これでできる）コピーと同じコピーと同じ
削除すぐ消す（ごみ箱には入れない）—（消えてほしくないときは、移動で退避用のフォルダへ）OS がエラーを返した
プロセス実行プログラムを起動する（シェルは通さない）プログラム（フルパスか、PATH から探す名前）と引数。成功とみなす終了コード（既定は 0 だけ）終了コードが成功でない、起動できない、外から止められた、時間の上限を超えた
  • .bat と .cmd はそのまま起動できる。.ps1 は、プログラムに powershell（か pwsh）を書き、引数を -File スクリプト にする。
  • 標準エラーへの出力は、成否に使わない（ffmpeg は、うまくいっていても途中経過を標準エラーに出す）。PowerShell の Write-Error だけでは成功に見えるので、失敗させたいときは exit 1 を書く。
  • 常駐するコアの PATH は、ターミナルの PATH と違うことがある（「ターミナルでは動くのに、常駐させると動かない」）。
  • 対象パスなどを引数に渡す書き方（${path} などのプレースホルダ）は、まだ決めていない（宿題一覧 4.3 に案）。

5. 発火からランへ

トリガー photos（作成・*.jpg）のジョブは thumbnail・backup・upload。依存は「upload は backup のあと」。cat.jpg の作成（検知 101）で発火すると、ジョブごとにランが 1 つずつできる。

backup が成功したとき

発火backup が成功
ラン 42 thumbnail
走っている
成功
ラン 43 backup
走っている
成功
ラン 44 upload
待っている走っている
成功

backup が失敗したとき

発火backup が失敗
ラン 42 thumbnail
走っている
成功
ラン 43 backup
走っている
失敗
ラン 44 upload
待っている
無視
  • 依存を書かなければ、ランは並行に走る。依存を書いたランは、依存先がすべて成功してから始める（合流もできる）。依存先が失敗・無視なら始めず、無視になる（理由「依存先が成功しなかった」）。
  • あるランが失敗しても、それに依存していないランは止まらない（上のラン 42）。
  • 同時実行数の上限（全体と、ジョブごと）に達していたら、ランは「待っている」で順番を待つ。無視にはしない。
  • 同じパスで同時に動ける発火は 1 つだけ（ロック）。発火中に届いた同じパスの変化は、捨てずに待ち表で待ち、今の発火が終わってから、もう一度発火する。
  • ランは、発火したときの設定で走る。依存でつながったランも同じ設定で走り、途中で設定を読み直しても変わらない。
  • 移動や削除のステップを持つジョブを、ほかのジョブと依存なしで並行にすると、設定の読み込み時に警告する（片方が移すと、もう片方が困るため）。

6. ランの終わり方と記録

結果いつラン 1 回ごとの出力のファイルに残すもの
成功すべてのステップが成功したステップごとの始まり・終わりの時刻と結果（終了コード）だけ
失敗ステップが失敗した、時間の上限を超えた、外から止められた（タスクマネージャーなど）上に加えて、すべてのプロセス実行のステップ（成功したものも）の、標準エラーの最後の 1 MB までと、標準出力の最後の数行（既定は 50 行。仮決め。設定ファイルで変えられる）
中断コアを止めた、コアが落ちた失敗と同じ
無視決まりに従って始めなかった作らない（ランが始まらないため）
  • 走っている間は、標準出力と標準エラーを、ステップごとに別々の一時ファイルへ OS が直接書く。ランが終わったら、Foxonar が結果を見てまとめ、一時ファイルを消す。
  • 組み込みのステップだけのランでも、出力のファイルを作る（ステップごとの時刻と結果を、同じ形で見られるように）。

時間の上限を超えたときと、コアを止める猶予を過ぎたときの、ステップの止め方：

OSまず、終わるように頼む待っても終わらなければ、強制的に止める
Linuxシグナル。子プロセスと、子が切り離さずに起動したプロセスへ頼んだ相手と同じ
WindowsCtrl+Break。同じ相手へ子プロセスだけ（頼んでも終わらない孫は、残ることがある）
  • 子が切り離して起動したプロセス（start "" notepad.exe の notepad など）は、どちらの OS でも止めない。
  • 組み込みのステップ（コピー・移動）は、Foxonar が自分で止め、書きかけの行き先を消してから止める。
