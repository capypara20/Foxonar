# コミット

## 1. 何をコミットするか確かめる

```bash
git status --short
git diff --stat
```

- 関係ない変更が混ざっていたら、どれを入れるか Roze に聞く
- 文書（`docs/`、`AGENTS.md`）が入るなら、先に突き合わせる。エラーがあれば止めて報告する

```bash
python scripts/doc_check.py --only-errors
```

## 2. メッセージを書く

これまでのコミットと同じ形にする（`git log -3 --format=%B` で見られる）。

```text
依存先の無視を決定し、ずれと論理の宿題を整理        ← タイトル：50 文字以内。何をしたかの要約

論理設計の第 2 弾で決めたことを反映した。          ← （あれば）1 行のまとめ

- 依存先のランが無視になったときも、後のジョブは始めない  ← 箇条書き
  （成功しなかったら始めない）。設計書 6 章と論点 M に追記  ← 続きは 2 字下げ

Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>  ← 最後に空行をはさんで、署名
```

- タイトル：50 文字以内（日本語なら 25 文字前後が目安）。文末に句点を付けない
- 本文：1 行は **72 桁以内**（全角は 2 桁と数える。日本語だけなら 35 文字前後）で改行する
- 本文は日本語。用語集の言葉を使う
- 署名の行は、そのときのシステムの指示（attribution）に合わせる

## 3. 形式を機械で確かめる

```bash
python .claude/skills/commit/check_msg.py <<'EOF'
（ここにメッセージ全文）
EOF
```

NG が出たら直して、もう一度確かめる。OK になるまで繰り返す。

## 4. Roze に見せてからコミットする

- メッセージと、入れるファイルの一覧を見せて、OK をもらう
- OK が出たら、同じ文面でコミットする

```bash
git add <ファイル>
git commit -F - <<'EOF'
（確かめたメッセージ全文）
EOF
```

- `git push` はしない（Roze が頼んだときだけ）
- コミットしたら、ハッシュを save-notes スキルで作業メモに残す
