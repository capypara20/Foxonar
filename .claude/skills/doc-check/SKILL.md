# 文書の突き合わせ

文書どうしのずれを、**機械**（スクリプト）と**目**（エージェント 2 人）の 2 段で調べ、Claude 自身が確かめてから Roze に報告する。

```
① スクリプト ──→ ② エージェント 2 人（並行）──→ ③ Claude が裏を取る ──→ ④ Roze に報告
  機械で分かるずれ     意味のずれ・抜け            誤検知を捨てる         直してよいもの／判断が要るもの
```

## ① スクリプトを走らせる

```bash
python scripts/doc_check.py --todo
```

- **エラー**：リンク切れ、無い論点への参照、閉じていないコードブロック、用語集の並び順の決まり違反（定義に、下で定義する言葉を使っている）
- **警告**：使わない言葉のうち機械で分かるもの（単独の「イベント」、「ルール」）
- **お知らせ**：決定していない論点、「残り」のある論点、英訳とのずれ
- **宿題**：設計書の「決めること」の一覧

## ② エージェントに読ませる（2 人を同時に）

Agent ツールで、次の 2 つを**1 つのメッセージで並行に**起動する。どちらも読むだけで、ファイルは変えない。

| エージェント | 見るもの |
|---|---|
| `term-guardian` | 言葉の使い方（定義どおりか、使わない言葉、層ごとの動詞、未定義の言葉を用語のように使っていないか） |
| `design-verifier` | 文書どうしの矛盾・反映漏れ・抜け（決定が用語集や設計書に書かれているか、「残り」が宿題に載っているか、考え漏れのケース） |

頼むときに渡すもの：

- 調べる範囲（全部か、`git diff --name-only` で分かる変更したファイルだけか）
- ① の結果（同じことを二度報告させないため）
- 「指摘には、ファイル名:行番号と、根拠になる文の引用を必ず付ける」

## ③ 裏を取る

エージェントの指摘は**そのまま信じない**。指摘ごとに、引用された行を自分で読んで確かめる。

- 引用が本当にそこにあるか
- 用語集・議論の記録の決定と、本当に食い違うか（文脈を読むと問題ないことがある）
- 確かめられなかったものは捨てるか、「未確認」と書く

## ④ Roze に報告する

次の 3 つに分けて、箇条書きで出す。各項目に `ファイル:行` を付ける。

1. **すぐ直せる書き間違い**：リンク、記号、言い回し、反映漏れのうち決定済みの内容を写すだけのもの
2. **Roze の判断が要るもの**：用語集の定義を変える必要があるもの、2 つの決定が食い違うもの、新しい言葉が要るもの。→ 論点を立てる候補として出す
3. **宿題の数**：設計書の「決めること」の件数と、増えた・減ったもの（全部は並べない。求められたら出す）

### 直すときの決まり

- 1 は、Roze が「直して」と言ったら直す。直したら ① をもう一度走らせ、エラー 0 を確かめる（ここがループ）
- 2 は直さない。**用語集の中身は、議論の記録に論点を立て、Roze が決めてから**変える
- 直したら、save-notes スキルで作業メモに残す
